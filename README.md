# 铭牌编号入仓前抽查核对

档案员在铭牌编号入仓前抽查录入是否准确。Flask + SQLite 网页应用, 用 Docker Compose 启动。

## 业务规则

- **开批**: 导入批号和含唯一条目号的铭牌编号清单; 为每批设定
  - 错录率上限: 0~99 的整数百分比;
  - 1~3 个严格递增的累计抽查数(检查点)。
  系统按种子随机无放回抽出有序名单, 抽样数 = 最大累计抽查数。
  同批号重传沿用原方案, 不重新抽样(清单不一致时给出提示)。
- **录入**: 核对结果可乱序录入; 每条只记首个结果, 重复录入拒绝; 结批后停止录入。
- **判定**: 从抽样第 1 条到某检查点全部核完才判定该点。假定全批错录数为刚超限的最小整数
  `D = ⌊N × 上限%⌋ + 1`, 计算该检查点抽到不多于实测错录数的超几何概率
  `P = P(X ≤ x)`, `X ~ Hypergeometric(N, D, n)`。
  `P ≤ 5% ÷ 检查点数` 即通过。
- **结批**: 在首个通过的检查点封存放行结论(检查点、抽查数、错录数、概率);
  所有检查点核完仍未通过则标为「待全检」。

## 大清单上传(内存约束)

清单文件以流式方式处理: 上传文件由 WSGI 服务器落到临时文件(不驻留内存),
应用按 64 KiB 分块做 UTF-8 增量解码并逐行解析, 每 1000 条批量写入当前连接
的 SQLite 临时表(`PRAGMA temp_store = FILE`, 落磁盘)。校验(格式、空值、
条目号重复)与同批号重传的配对集合比对全部在临时表上用 SQL 完成。

因此**行长与最大检查点固定时, 从接收文件到校验、抽样、同批号重传比对的额外
内存不随总行数增长**; 服务进程只保留一个读块、当前行和 1000 条的写入缓冲。
全量条目仍全部写入 `items` 表, 只有被抽中的 n_max 条设置 `position`。

- 上传清单以 UTF-8 解码, 非法 UTF-8 整份拒绝。
- 开新批与同批号重传都会逐行校验整份清单; 任一行格式错误或条目号重复都会
  整批拒绝, 不写 `batches`/`items`。
- 开批写入失败(SQLite 错误等)在单个事务内回滚, 不留新批次或零散条目。
- 重传比对只比较「条目号, 铭牌编号」配对集合: 调换行序仍视为相同清单,
  只有配对集合变化时才提示「清单不一致」。

## 启动(Docker Compose)

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据保存在命名卷 `nameplate-data` 中。

## 本地运行(无 Docker)

```bash
pip install -r requirements.txt
python3 wsgi.py          # 或 flask --app wsgi run
```

## 网页演示流程

1. 「开批」页: 填批号、错录率上限、累计抽查数、清单(可点「填入演示数据」一键填充), 提交后生成有序抽样名单。
2. 批次详情页: 按名单核对并逐条录入「正确/错误」(可乱序); 演示辅助按钮可把当前检查点未核条目批量提交。
3. 每核完一个检查点的前缀即自动判定; 通过后封存「放行」结论, 全部未通过则标「待全检」。
4. 「批次查询」页查看所有批次状态与封存结论。

## JSON API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/batches` | 开批 `{batch_no, limit_pct, checkpoints[], items[{entry_no,nameplate_no}], seed?}`; 同批号返回 200 且 `created=false` |
| GET | `/api/batches` | 批次列表 |
| GET | `/api/batches/<批号>` | 详情: 方案、有序抽样名单、检查点进度、判定记录、封存结论 |
| POST | `/api/batches/<批号>/results` | 录入 `{entry_no, result: "ok"\|"err"}`; 返回本次触发的判定 |

## 自测

```bash
python3 -m pytest tests/ -v              # 常规用例(默认跳过 slow)
python3 -m pytest tests/ -v -m slow      # 30 万条大清单内存/耗时用例
```

覆盖: 超几何概率与组合数参照实现比对、刚超限错录数、阈值; 开批抽样(有序、无放回、种子可复现,
并与改造前 `random.sample` 的抽中顺序逐条比对)、同批重传沿用原方案与配对集合比对、
流式解析(CRLF/末尾无换行/分块边界)、重复条目/坏行/非法 UTF-8/写库失败均不留批次或条目、
乱序录入、只记首个结果、未抽中/未知条目拒录、前缀未齐不判定、
首个通过检查点封存放行、全部未通过标待全检、结批后拒录、网页表单流程。
