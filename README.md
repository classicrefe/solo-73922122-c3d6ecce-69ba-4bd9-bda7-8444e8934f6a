# 铭牌编号入仓前抽查核对

档案员在铭牌编号入仓前抽查录入是否准确。Flask + SQLite 网页应用, 用 Docker Compose 启动。

## 业务规则

- **开批**: 导入批号和含唯一条目号的铭牌编号清单; 为每批设定
  - 错录率上限: 0~99 的整数百分比;
  - 1~3 个严格递增的累计抽查数(检查点)。
  系统按种子随机无放回抽出有序名单, 抽样数 = 最大累计抽查数。
  同批号重传沿用原方案, 不重新抽样(清单不一致时给出提示)。
- **录入**: 核对结果可乱序录入; 每条只记首个结果, 重复录入拒绝; 结批后停止录入。
- **判定**: 从抽样第 1 条到某检查点全部核完才判定该点。假定全批错录数为刚超限的最小整数
  `D = ⌊N × 上限%⌋ + 1`, 计算该检查点抽到不多于实测错录数的超几何概率
  `P = P(X ≤ x)`, `X ~ Hypergeometric(N, D, n)`。
  `P ≤ 5% ÷ 检查点数` 即通过。
- **结批**: 在首个通过的检查点封存放行结论(检查点、抽查数、错录数、概率);
  所有检查点核完仍未通过则标为「待全检」。

## 启动(Docker Compose)

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据保存在命名卷 `nameplate-data` 中。

## 本地运行(无 Docker)

```bash
pip install -r requirements.txt
python3 wsgi.py          # 或 flask --app wsgi run
```

## 网页演示流程

1. 「开批」页: 填批号、错录率上限、累计抽查数、清单(可点「填入演示数据」一键填充), 提交后生成有序抽样名单。
2. 批次详情页: 按名单核对并逐条录入「正确/错误」(可乱序); 演示辅助按钮可把当前检查点未核条目批量提交。
3. 每核完一个检查点的前缀即自动判定; 通过后封存「放行」结论, 全部未通过则标「待全检」。
4. 「批次查询」页查看所有批次状态与封存结论。

## JSON API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/batches` | 开批 `{batch_no, limit_pct, checkpoints[], items[{entry_no,nameplate_no}], seed?}`; 同批号返回 200 且 `created=false` |
| GET | `/api/batches` | 批次列表 |
| GET | `/api/batches/<批号>` | 详情: 方案、有序抽样名单、检查点进度、判定记录、封存结论 |
| POST | `/api/batches/<批号>/results` | 录入 `{entry_no, result: "ok"\|"err"}`; 返回本次触发的判定 |

python3 -m pytest tests/ -v

同批重传沿用原方案、乱序录入、只记首个结果、未抽中/未知条目拒录、前缀未齐不判定、
首个通过检查点封存放行、全部未通过标待全检、结批后拒录、网页表单流程。
